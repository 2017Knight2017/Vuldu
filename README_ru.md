# Vuldu

**Vul[kan] du[um]** это порт Doom, написанный мной 
с полного нуля на Rust, с рендерингом на Vulkan и 
паттерном ECS в игровом цикле. Финальная цель проекта 
-- добиться максимальной производительности на больших
картах при помощи многопоточных вычислений, что в 
оригинальном *Id Tech 1* было фундаментально невозможно.

## Инструкция по запуску
*Примечание: для Vuldu необходимо иметь GPU с 
поддержкой Vulkan 1.3.*

Первым делом, скачайте новейший 
[релиз](https://github.com/2017Knight2017/Vuldu/releases), 
а также wad, который вы хотите запустить (например,
DOOM2.WAD). Для запуска откройте командную строку в
папке игры и пропишите:

```bash
./vuldu -i your/path/to/DOOM2.WAD 
```

Вы можете ознакомиться с параметрами приложения 
с помощью `./vuldu -h`

## Стек технологий
- *[winit](https://github.com/rust-windowing/winit)* 
=> Управление окном
- *[hecs](https://github.com/Ralith/hecs)* 
=> Реализация ECS мира и сущностей
- *[rodio](https://github.com/rustaudio/rodio)* 
=> Пространственное аудио
- *[serde](https://github.com/serde-rs/serde)* 
=> Парсинг toml-таблиц
- *[cxx](https://github.com/dtolnay/cxx)* 
=> FFI-мост между Rust и рендерером на C++
- Алгоритм *[earcut](https://github.com/georust/earcut)*
=> Триангуляция полов

---
- *[rayon](https://github.com/rayon-rs/rayon)* 
и 
*[micropool](https://github.com/DouglasDwyer/micropool)* 
=> Распараллеливание 
вычислений 

Важно отметить, что я намеренно выбрал две библиотеки 
для многопоточности, так как они работают по-разному и
решают противоположные задачи: 

*Rayon* заточена на максимальную производительность.
Она этого добивается при помощи **кражи работы**: если 
поток закончил выполнять свою работу, то он отбирает
части работы у другого потока. Оно работает идеально 
для подготовки данных во время загрузки.

Однако практика показывает, что "кража работы" 
нестабильна, когда от неё зависит фреймрейт игры. 
Поэтому я выбрал *micropool* который работает по
принципу **активного ожидания**: после завершения
работы потоки не засыпают, а ждут, чтобы как можно 
скорее приступить к выполнению следующей. Оно работает
идеально, когда надо обработать больше данных без 
сильного увеличения нагрузки.

## Архитектура проекта
Дизайн проекта таков, что крейты слабо связаны друг
с другом в *строго одностороннем порядке*:
<center><b> ↓ Renderer ↓</b></center>

<center><b> > App < </b></center>

<center><b> ↑ Engine ↑ </b></center>

<center><b> ↑ Wad Parser ↑ </b></center>

### Renderer
FFI-мост ведёт в `renderer_cpp/`, где класс Vulkan
реализован на C++ и безопасно абстрагирован в 
`src/lib.rs` для последующего применения его методов в 
Rust. Графический конвейер построен с мыслью о 
**массовой обработке ресурсов** и минимизации вызовов
отрисовки.

Объекты и UI активно используют **Instancing**, 
позволяющий десяткам тысяч экземплярам отображаться
на экране почти без влияния на FPS.

### Wad Parser
В этом крейте байты из wad превращаются в текстуры и
уровни. Всё управление ресурсами файлов работает через
объект `WadManager`, который хранит lumps с привязкой к
своему файлу-источнику.

В `src/textures/` текстуры из patch-формата 
конвертируются в массив индексов цветов PLAYPAL. В 
`src/vertices/` секторы и окружающие их linedefs 
триангулируются в полы и стены и превращаются в 
полноценную 3D-сцену.

### Engine
Здесь живут все ECS системы, связанные с движением,
зрением, распространением звука и т.д. *Engine* может 
изменять данные уровня и сущностей в ходе геймплея.

Кода, вдохновлённого 
[исходниками](https://github.com/id-Software/DOOM/tree/master/linuxdoom-1.10) 
Джона Кармака, здесь больше, чем где-либо ещё в проекте.

### App
Главный координационный центр проекта. В 
`App::resumed()` находится код инициализации окна, а в
`WindowEvent::RedrawRequested` код его перерисовки. 

В целом, в *App* все остальные крейты сливаются воедино 
в виде `GraphicsContext` и `GameContext`, а также идёт 
работа с аудио и пользовательским вводом.

## Cборка
Для локальной сборки необходим 
[Vulkan SDK](https://vulkan.lunarg.com/sdk/home). После 
его установки нужно клонировать репозиторий на ваш
компьютер:

```bash
cd your/local/path
git clone https://github.com/2017Knight2017/Vuldu.git
```

Туда же положите wad (например, DOOM2.WAD), который вы
планируете запускать. После этого, скомпилируйте и 
запустите проект с помощью cargo:

```bash
cargo build
cargo run -- -i DOOM2.WAD
```
